# RapiDoc Portal Starter

A developer portal for your OpenAPI specs, built with **[RapiDoc Portal](https://portal.rapidocui.com)**: API reference, Markdown and Markdoc guides, search, and an MCP endpoint for AI agents. Deploy this starter in one click, then make it yours.

## Make it yours

The buttons deploy this repository as it is. To publish your own APIs:

1. Click **Use this template** on GitHub to get your own copy, and clone it.
2. Replace `specs/api.yaml` with your OpenAPI specs and list them under `apis:` in `rapidoc.config.yaml`.
3. Edit the pages in `docs/` and the header, navigation and theme in `rapidoc.config.yaml`.
4. Deploy your copy:
   - **Render**: Dashboard → New → Blueprint → your repository. It reads `render.yaml`.
   - **DigitalOcean App Platform**: Create App → GitHub → your repository. It detects the build and start scripts.
   - **Railway**: New Project → Deploy from GitHub repo → your repository. It detects the build and start scripts. Set the health check path to `/_rapidoc/health` and generate a domain under Networking.

Every push to your repository then rebuilds the portal.

## Run it locally

```bash
npm install
npm run dev        # live preview with hot reload
npm run build      # build the portal into dist/
npm start          # serve dist/ like the hosts do (rapidoc serve, on $PORT or 8080)
npm run validate   # check every spec in apis: against the OpenAPI schema
```

## How the hosts run it

All three run the same two scripts from `package.json`:

| Step | Command |
| :--- | :--- |
| Build | `npm run build` (`rapidoc build`) |
| Start | `npm start` (`rapidoc serve`, listening on `$PORT`) |
| Health check | `GET /_rapidoc/health` |

`@rapidoc/cli` and `@rapidoc/server` are dependencies, not dev dependencies, so the portal still starts on hosts that drop dev dependencies after the build. Without sign-in, `dist/` is a plain static site, so a static host (GitHub Pages, Netlify, Cloudflare Pages) can serve it too.

**Plans and cost:** Render's free web service sleeps after 15 minutes without visits, and the next visit waits up to a minute while it wakes. DigitalOcean's template uses its smallest paid instance. Railway bills by usage. Check each host's current pricing.

## Add sign-in

To put some pages behind your company's sign-in (OpenID Connect: Auth0, Okta, Microsoft Entra ID, Keycloak, ...), uncomment `auth:` and `access:` in `rapidoc.config.yaml` and set the secrets as environment variables on the host: `RAPIDOC_SESSION_SECRET` (32+ random characters), `RAPIDOC_AUTH_CLIENT_SECRET` and `RAPIDOC_PUBLIC_URL`. See [Deploy with rapidoc serve](https://portal.rapidocui.com/docs/deploy/rapidoc-serve/).

## Project structure

```text
├── docs/                    # Documentation pages (.md, .markdoc, .mdx); docs/index.* is the home page
├── specs/                   # OpenAPI specifications (.yaml, .json)
├── rapidoc.config.yaml      # Portal header, navigation tabs, theme and APIs
├── render.yaml              # Render Blueprint
├── .do/deploy.template.yaml # DigitalOcean template for the Deploy to DO button
└── package.json
```
